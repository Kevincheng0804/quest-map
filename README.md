# AI 任務闖關地圖（Claude Code 外掛）

跑 Claude Code 的時候，它待在你的桌面上：一張永遠在最上層的闖關地圖，可以縮成螢幕邊緣的水位。你做自己的事，想知道進度就瞄一眼。

## 安裝與更新

需要 Node.js 18 以上。下面的 `<你的帳號>` 換成放這個專案的 GitHub 帳號。

### Claude Code

```bash
claude plugin marketplace add <你的帳號>/quest-map
```

```bash
claude plugin install quest-map@ai-quest-map
```

開一個新的 Claude Code 對話，輸入：

```
/quest-map:open
```

第一次會下載桌面視窗元件（Electron，約 100 MB，一兩分鐘），裝在使用者資料夾的 `.quest-map/runtime`，Claude Code 和 Cowork 共用。之後每次開新的 Claude Code 工作階段，地圖會自己打開。

**更新**：

```bash
claude plugin marketplace update ai-quest-map
```

```bash
claude plugin update quest-map@ai-quest-map
```

然後開新的對話，輸入 `/quest-map:open`。如果地圖還開著舊版，這個指令會自動把它換成新版（0.11.0 以後的版本才有這個功能，從更舊的版本升級時要先手動關掉舊地圖一次）。

### Cowork

1. 打開 Claude 桌面版，到 **Customize > Plugins**。
2. **Add > Add marketplace**，輸入 `<你的帳號>/quest-map`。
3. 找到 quest-map 按 **Install**。
4. 想要自動更新就打開 **Sync automatically**；要手動更新就按 **Check for updates**。

Cowork 的工具啟動時，如果地圖沒開而且元件已經裝好，會自己把地圖打開。第一次請先在 Claude Code 輸入一次 `/quest-map:open` 把元件裝好。

### 沒有 GitHub、只有 zip 的時候

把 zip 解壓縮，在解壓出來的資料夾旁執行：

```bash
claude plugin marketplace add ./quest-map
```

```bash
claude plugin install quest-map@ai-quest-map
```

Cowork 可以在 Plugins 頁選 **Add > Upload plugin**，上傳 `quest-map.plugin`。

## 地圖看得到哪些對話

| 哪裡的對話 | 地圖看得到嗎 | 怎麼運作 |
|---|---|---|
| **在你電腦上執行的** Claude Code | 看得到，全自動 | hooks 把事件送到你電腦上的地圖 |
| Cowork 的多步驟任務 | 看得到，但要 Claude 主動回報 | Claude 呼叫 `quest_plan`；問答、聊天、翻譯它通常不會 |
| **雲端的** Claude Code 對話（網頁版、或桌面版選了雲端） | **看不到** | 對話跑在雲端的虛擬機，連不到你電腦上的地圖 |
| 一般聊天（Chat） | **看不到** | 官方文件：聊天會忽略外掛的 hooks 和本機 MCP |

地圖待命時顯示「等待連線」，意思是它沒收到任何事件。通常是上面「看不到」的情況，或是外掛更新前開的舊對話（開新對話就好）。

**怎麼分辨我的 Claude Code 對話是在本機還是雲端**：開新的工作階段時，環境選在你的電腦上執行（Local），不要選雲端。雲端的對話跑在遠端的 Linux 虛擬機裡，網址是 `claude.ai/code/...`。按鈕名稱以你桌面版實際畫面為準。在雲端對話裡，外掛會直接告訴 Claude「這裡連不到地圖」，不會浪費工具呼叫，`/quest-map:open` 也會說明原因。

## 外掛裡有什麼

| 元件 | 做什麼 |
|---|---|
| Hooks | 自動把進度送到地圖：你說了什麼、待辦清單的變化、Claude 是不是在等你、是不是停了。不花 Claude 的注意力 |
| MCP 工具 `describe_quest` | 讓 Claude 替每一關補上白話標題、白話說明、技術細節、世界名稱，並把每個任務拆成 2 到 5 個小步驟 |
| MCP 工具 `quest_progress` | 讓 Claude 每做完一個小步驟回報一次，水位照比例漲 |
| Skill `plain-levels` | 教 Claude 什麼時候呼叫上面的工具、白話要怎麼寫、小步驟怎麼拆 |
| Skill `open`（`/quest-map:open`） | 打開桌面視窗，第一次負責下載 |
| 桌面程式 `app/` | 地圖視窗、邊緣水位、本機接收埠 127.0.0.1:47600（可用 `QUEST_PET_PORT` 改） |

狀態由 hooks 負責，文字由 Claude 負責。就算 Claude 忘了呼叫工具，地圖照樣會動，只是關卡名稱會是待辦清單的原文。

## 三種大小

| 狀態 | 怎麼切換 |
|---|---|
| 一般大小 | 預設。拖上方那一條可以移動視窗 |
| 縮放 | 拉視窗邊角，地圖等比縮放（最小 480×300） |
| 最小化成邊緣水位 | 按右上「縮到旁邊」。地圖收起來，螢幕邊緣出現水位，旁邊有一個小把手。點把手展開地圖；按住可以拖到別處，放開會自動貼回最近的左緣或右緣 |

地圖視窗的大小和位置、把手貼在哪一邊的哪個高度、上次是地圖還是邊緣水位，都會記住，下次開啟照舊。

### 邊緣水位

螢幕左右兩側各有一條細細的水柱，底部相連，像一個杯子。滑鼠點擊會穿透過去，不會擋到你操作。

- **一個任務一杯水**：Claude 把工作拆成多個任務，每個任務是一杯。任務進行中，上方有水流倒下來，水面帶著波浪慢慢往上漲。
- **倒滿**：任務完成時水漲到頂、亮一下，然後退掉，換下一杯。把手上的數字（例如 3/10）是已經倒滿幾杯。
- **等你**：Claude 需要你同意或回答時，水變成橘色並明暗閃爍，把手變成橘色鎖頭、顯示「等你」，同時跳一則系統通知。
- **全部完成**：水變成綠色，四邊連成一圈。

任務進行中的水位怎麼算：Claude 會先把每個任務拆成幾個小步驟，每做完一步回報一次，水位就照比例漲（4 步做完 1 步是四分之一杯）。同一步裡面，水會隨著它動工具再慢慢補一點，但不會超過下一格。Claude 忘了回報時，退回用「這個任務已經動了幾次工具」來估，最多到九成。不管哪一種，任務真正標成完成才會倒滿。

在地圖上點一個關卡，右下的說明卡會列出它的小步驟和打勾狀況。

顏色和粗細集中在 `plugins/quest-map/app/edge.html` 最上面的 `LOOK`：水柱寬度、底部厚度、淡藍與深藍、等你的橘色、完成的綠色。

### 小機器人的四種心情

地圖上的小機器人會跟著狀況換表情。

| 心情 | 什麼時候 | 樣子 |
|---|---|---|
| 做事中 | 有關卡正在進行 | 圓眼睛會眨、上下輕跳 |
| 等你 | Claude 需要你同意或回答 | 八字眉、冒汗、左右發抖，天線變橘色 |
| 開心 | 這個世界的關卡全部通關 | 笑眼、張嘴笑、旁邊有星星、跳得更高 |
| 休息 | 還沒開始，或 Claude 停下來了 | 閉眼、冒出 z、慢慢呼吸 |

## 小修改也看得到在做什麼

請 Claude 改一個小東西時，它通常不會列待辦清單，整件事只有一關。這時地圖靠 Claude 每次動工具的事件，即時顯示在做什麼，不需要 Claude 配合：

- **泡泡**：「正在看 index.html」「正在修改 style.css」「正在跑測試」「正在搜尋檔案」。工具做完後會換成過去式，留到下一個動作開始，例如「改好了 style.css，想下一步…」，Claude 思考的那幾秒也看得到剛剛做了什麼。有待辦清單時會帶上關卡名稱：「在『做出表單畫面』這關：正在修改 style.css…」。
- **說明卡**：點關卡後，右下角顯示「現在／剛剛：…」，以及「這次動過的檔案」清單（「改了 style.css」「寫入 post.md」）。「這次」是指你上一句話之後。
- **白話說明這次在改什麼功能**：沒有待辦清單的小修改，Claude 開始動手前會先補一句白話（用 `describe_quest`，只多一次呼叫），例如「把按鈕改紅色：把送出按鈕的顏色改成紅色，讓人更容易看到」。這句話成為這一關的名稱和說明，泡泡變成「在『把按鈕改紅色』這關：正在修改 style.css…」，不是只看到檔名。這需要 Claude 配合；它沒補的話，會退回只顯示動作。
- **完成時的一句話**：Claude 收尾訊息的第一句會顯示在泡泡，例如「完成：已經把送出按鈕改成紅色」。有白話說明時，說明卡維持白話，不被收尾那句技術性的話蓋掉。
- **只顯示檔名，不顯示完整路徑；跑指令只顯示類別**（跑測試、安裝套件、儲存版本紀錄…），不顯示指令內容，因為指令裡可能有密碼或金鑰。

### 什麼時候算完成

以計畫為準：

- **有待辦清單**：所有沒被拆除的關卡都通關才算完成，**包括你中途自己加的分支**。Claude 停下來只代表停在半路，不算完成，也不顯示總結。
- **沒有待辦清單的小任務**：整個要求就是計畫，Claude 收尾（而且不是用問句結尾）時算完成。你在做到一半時追加要求，算同一個任務，要等之後那次收尾才完成。

## 在 Cowork 使用

Cowork 是 Claude 桌面版的任務模式（右側有「進度」面板）。

**實測結果（Windows）**

- Cowork 載入的 MCP 伺服器跑在你的電腦上，連得到地圖；Claude 也會照 MCP 的說明做事。
- **Cowork 的 hooks 沒有把事件送到地圖**（`/stats` 裡沒有任何來自 Cowork 的 `PreToolUse`、`Stop` 等事件），所以 Cowork 不能像 Claude Code 那樣自動同步。
- Cowork 的 MCP 伺服器沒有專案資料夾（`CLAUDE_PROJECT_DIR` 是空的，工作目錄是 `C:\WINDOWS\system32`）。

**所以 Cowork 用 `quest_plan`**：Claude 在任務一開始送出整份步驟清單，之後每次進度有變動（開始某一步、做完某一步、新增或拿掉步驟）就再送一次完整清單，內容跟 Cowork 的進度面板一樣。地圖沿用同一套比對邏輯，所以新增、拆除、回頭修、完成判定都跟 Claude Code 一樣。

- Cowork 的任務是**獨立的對話**，在清單裡叫「Cowork・任務名稱」，不會跟 Claude Code 的對話混在一起。左下角的標籤是「這次的任務」。
- 需要你動手時，Claude 填 `waiting_for`，那一步變成橘色「等你」，邊緣水位也會變橘色。
- 全部步驟完成才算完成；做完時 Claude 會寫一句白話結果，顯示在泡泡。
- 沒有專案資料夾的 MCP 呼叫一律歸到 Cowork 的對話，不會再貼到 Claude Code 的對話上。

**讓 Cowork 更常主動回報**：MCP 說明和技能都寫了「在 Cowork 做超過一個步驟的工作（下載、整理檔案、寫程式、研究後產出檔案）就主動用 `quest_plan`，單純問答不用」。我在模擬 Cowork 的測試裡讓 Claude 做了 3 個沒提到 `quest_plan` 的多步驟工作，它 3 次都主動用了；另外 1 個純問答沒有用。樣本很小，只是模擬（不是真的 Cowork），不保證每次都會。想更穩，可以在 Claude 桌面版設定裡（如果有「自訂指示」之類的欄位）放一句「做超過兩步的工作時，請用 quest_plan 回報進度」；這個我沒有驗證在 Cowork 是否生效。

**限制**：全部靠 Claude 記得呼叫，沒有「正在修改 style.css」這種自動動作，也偵測不到「等你按同意」。進行中的那一步水位固定從 30% 起跳（沒有工具事件可以估）。

**測試用的步驟**

1. 先讓地圖在電腦上跑起來：在 Claude Code 輸入一次 `/quest-map:open`（元件裝在使用者資料夾的 `.quest-map\runtime` 或外掛專用位置）。
2. 打開 Claude 桌面版，到 **Customize > Plugins**，先移除舊的 quest-map，再 **Add > Upload plugin** 上傳 `quest-map.plugin`。
3. 開新的 Cowork 任務，輸入一個要好幾步的工作，例如：「幫我在工作資料夾建立 hello.txt，內容寫 hi，再確認內容。請先把步驟加到進度清單。」
4. 看地圖左上角的清單有沒有出現「Cowork・…」，以及關卡有沒有跟著 Cowork 的進度面板變化。
5. 瀏覽器開 `http://127.0.0.1:47600/stats`，裡面會有 `mcp:chatplan` 的次數。

**這個對話有沒有連到地圖**：瀏覽器開 `http://127.0.0.1:47600/stats`，看 `sessionList`。每個對話一列：名稱、完成數／總數、是不是在等你、最後一次有動靜的時間（沒有你說的話、指令或檔案內容）。你正在用的對話沒有出現在裡面，就是它沒有送事件給地圖：多半是舊對話，開新對話就好。

**排查連線**：

1. 先讓地圖在電腦上跑起來：在 Claude Code 輸入一次 `/quest-map:open`（第一次要下載元件，之後 Claude Code 和 Cowork 共用同一份，放在使用者資料夾的 `.quest-map\runtime`）。
2. 打開 Claude 桌面版，到 **Customize > Plugins > Add > Upload plugin**，上傳 `quest-map.plugin`。
3. 開新的 Cowork 任務，輸入：「請呼叫 quest_ping 告訴我結果，然後在工作資料夾建立 hello.txt，內容寫 hi。請先把步驟加到進度清單。」
4. 用瀏覽器打開 `http://127.0.0.1:47600/stats`，看地圖程式收到了什麼。

`/stats` 會列出收到的事件名稱和次數（例如 `PreToolUse:Read`、`mcp:describe`、`mcp:quest_ping`），以及最後一次連線測試是從哪裡來的。裡面沒有指令或檔案內容。可以用它判斷：Cowork 的 hooks 有沒有送事件、進度清單用哪個工具名稱、MCP 伺服器有沒有連到地圖。

`quest_ping` 會分辨三種結果：

| 回報 | 代表什麼 | 怎麼辦 |
|---|---|---|
| 成功，闖關地圖有收到 | 連上了，而且是新版 | 看 `/stats` 判斷 hooks 有沒有送事件 |
| 地圖有開，但是舊版（對方回 404） | 電腦上跑的是舊版地圖，沒有連線測試功能 | 完全關掉地圖再重新打開（見下方「關不掉舊版」） |
| 失敗，連不到闖關地圖 | 沒開，或這個環境連不到你電腦上的地圖 | 先在 Claude Code 輸入 `/quest-map:open` 把地圖開著 |

瀏覽器開 `http://127.0.0.1:47600/stats` 看到 **404**，代表有程式在回應，但它是舊版（沒有 `/stats`）。看到「無法連線」才是地圖沒開。新版的 `/stats` 開頭會寫 `"version"`，也可以開 `http://127.0.0.1:47600/version` 看版本。

**關不掉舊版**：在 PowerShell 先看有哪些程序（只列出，不會關任何東西），確認路徑是闖關地圖的，再關掉：

```powershell
Get-Process electron -ErrorAction SilentlyContinue | Select-Object Id, Path
```

```powershell
Get-Process electron -ErrorAction SilentlyContinue | Stop-Process
```

這個外掛的 MCP 伺服器會在啟動時，如果地圖沒開而且元件已安裝，自動把地圖打開（不下載、不出聲）。想關掉：設定環境變數 `QUEST_PET_NO_AUTOLAUNCH=1`。

一般聊天（claude.ai 網頁、手機、桌面版的一般對話）不支援：外掛的 hooks 和本機 MCP 伺服器在聊天裡都會被忽略，連不到你電腦上的地圖。

## 同時跑多個 Claude Code

每個 Claude Code 對話各有一份進度，彼此不會混在一起。

- **對話清單**：開了 2 個以上對話時，地圖左上角「目前位置」下方會出現清單，每列有專案名稱、小進度條和進度。點一列就切換過去，之後畫面固定顯示它，不會被別的對話搶走。沒點過時，畫面自動跟著最近有動靜的那一個。
- **名稱**：用專案資料夾的名稱，重複的加編號，例如 `club-signup`、`club-signup #2`。
- **邊緣水位代表你選的那一個**：水位高度是你選的對話的進度。
- **任何一個對話在等你，都會提醒你**：不管你選的是哪個，只要有對話等你同意或回答，邊緣的水就變橘色，小把手顯示「等你 · 專案名」，清單上那一列變橘色，地圖收起來時還會跳系統通知，寫明是哪個專案。
- **對話結束就從清單消失**：關掉 Claude Code 後會自動移除；超過 6 小時沒動靜的也會移除。
- **白話名稱和小步驟不會貼錯對話**：Claude 補的白話名稱、回報的進度，依專案資料夾對到正確的對話。



| Claude Code 發生的事 | 地圖上的變化 |
|---|---|
| 你送出一句話 | 更新「你剛剛說」；上一批關卡全通關的話，收合成一個已通過的世界 |
| Claude 建立或更新待辦清單 | 每個待辦是一關；新增、消失、做完又改回未完成，分別變成新關卡、已拆除、回頭修，原因引用你最近那句話 |
| Claude 要你按同意，或用問句結束回覆 | 目前那關變成「等你開門」 |
| Claude 停下來 | 泡泡說明是做完了還是停在半路 |

關卡超過 7 個時，地圖只畫角色附近的 7 關，其餘用「前面 N 關已走過／後面還有 N 關」表示。

## 已知限制

- Claude 沒有列待辦清單的小任務，整件事會顯示成一關；只靠工具動作看進度，水位是估的。
- 工具跑得很快時，「正在…」只會閃一下（事件每 120 毫秒合併畫一次），主要看到的是做完後的「改好了…，想下一步」。
- 「做到一半插話，二選一」的情境只在網頁示範裡有；Claude Code 本身沒有這個選擇。
- 兩個對話開在**同一個資料夾**時，清單上會分成兩列（資料夾名稱加編號），但白話名稱和進度只能貼到其中最近有動靜的那一個，可能貼錯。
- **按下「同意」之後，地圖要等那個工具做完才會更新。** Claude Code 在你按同意的那一刻沒有發任何事件，只有工具成功（`PostToolUse`）或失敗（`PostToolUseFailure`）才會通知。所以工具要跑很久（下載、瀏覽器、長指令）時，橘色「等你開門」會一直在。橘色泡泡會寫「已等 N 分鐘」，超過 2 分鐘會提醒你「如果你已經按過同意，這一步做完地圖才會更新」。
- **外掛更新或換來源之後，舊的對話不會有新的 hooks，要開新對話。** 舊對話載入的是舊的設定（有時指向已經刪掉的資料夾），事件送不到地圖，地圖上就不會出現那個對話。
- 雲端的 Claude Code 對話、一般聊天，地圖看不到（見上面「地圖看得到哪些對話」）。要讓雲端對話的進度傳回你的電腦，需要一個雙方都連得到的中繼服務，或讀取你的對話紀錄，目前沒有做。
- 排程任務（`<scheduled-task ...>`）開始時是一般的 `UserPromptSubmit`，所以地圖上「你剛剛說」會顯示那一串文字。
- 只在 Linux 的虛擬螢幕上實際跑過；Windows 和 macOS 還沒驗證。

## 開發

```bash
cd plugins/quest-map/app
```

```bash
npm install
```

```bash
npm start
```

跑自動測試（關卡翻譯邏輯與視窗擺放計算，共 124 項）：

```bash
npm test
```

不接 Claude Code 也能看效果：`npm start` 之後另開終端機跑 `npm run demo`。用 `QUEST_PET_DEBUG=1` 啟動會把收到的事件記到程式資料夾的 `events.log`。

- `quest-map.html`：地圖本體，也是網頁示範版的來源。改完跑 `npm run build` 產生 `app/map.html`
- `plugins/quest-map/app/state.js`：把 Claude Code 事件翻成關卡
- `plugins/quest-map/app/main.js`：桌面視窗與本機接收埠
- `plugins/quest-map/app/placement.js`：把手貼邊與視窗位置還原的計算
- `plugins/quest-map/app/edge.html`：邊緣水位；`battery.html`：水位旁的小把手
- `plugins/quest-map/app/mcp-server.js`：MCP 伺服器（零相依）
- `plugins/quest-map/app/launch.js`：啟動器；`runtime.js`：找桌面元件、自動啟動地圖；`stats.js`：`/stats` 的事件統計
