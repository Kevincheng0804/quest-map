# AI 任務闖關地圖

把 Claude 正在做的事，畫成一張闖關地圖，放在你的桌面上。

你請 Claude 做事，然後去做自己的事。想知道它做到哪了，瞄一眼地圖就好：每個步驟是一個關卡，一個小機器人沿著路往前走，Claude 在等你同意的時候，會亮橘色提醒你。不用懂程式也看得懂。

- **關卡**：Claude 的每個步驟是一關，用顏色和圖示表示做到哪了。
- **邊緣水位**：地圖可以縮成螢幕兩側的淡藍色水位，一個任務是一杯水，做完就倒滿。
- **會提醒你**：Claude 需要你同意或回答時，關卡變橘色、水位變橘色，地圖縮起來時還會跳系統通知。
- **白話說明**：Claude 會把「建立 form.html」寫成「做出表單畫面」，技術細節放在最後一行。

支援在你電腦上執行的 **Claude Code**（命令列、Claude 桌面版的 Code 分頁）和 **Cowork**。**不支援**一般聊天與雲端的 Claude Code，詳見[地圖看得到哪些對話](#地圖看得到哪些對話)。

## 開始使用

### 需求

- 一台 **Windows** 電腦（我在 Windows 上實測過；macOS 和 Linux 桌面沒有驗證，見[使用限制](#使用限制)）。
- **Node.js 18 以上**，而且要在系統的 PATH 裡（外掛的 hooks 用 `node` 指令執行）。在終端機輸入 `node --version` 確認。
- **git**（從 GitHub 加入市集時會用到）。
- **Claude Code** 或 **Claude 桌面版**。
- 約 100 MB 的硬碟空間，第一次會下載桌面視窗元件（Electron）。

### 1. 安裝

**Claude Code（命令列）**

```bash
claude plugin marketplace add Kevincheng0804/quest-map
```

```bash
claude plugin install quest-map@ai-quest-map
```

**Claude 桌面版（Code 分頁與 Cowork）**

1. 打開 Claude 桌面版，到 **Customize > Plugins**。
2. 按 **Add > Add marketplace**，輸入 `Kevincheng0804/quest-map`。
3. 找到 **AI 任務闖關地圖**，按 **Install**。
4. 想自動更新的話，打開這個市集的 **Sync automatically**。

命令列和桌面版是**各自獨立**的兩份安裝，用哪邊就裝哪邊；兩邊都用就兩邊都裝。

### 2. 打開地圖

在 Claude Code 的對話框輸入：

```
/quest-map:open
```

第一次會下載桌面視窗元件，要一兩分鐘，之後不用再下載。裝好之後，每次在你電腦上開新的 Claude Code 對話，地圖會自己打開，不用再輸入指令。

> 這行指令是在 **Claude Code 的對話框**裡輸入，不是貼在 PowerShell 的命令列。命令列版要先輸入 `claude` 進入對話，再輸入它。

### 3. 照常使用

像平常一樣請 Claude 做事，地圖會自己動。

**重要**：在桌面版 Code 分頁開新工作階段時，環境要選**在你的電腦上執行（本機）**，不要選雲端，否則地圖看不到。

## 地圖看得到哪些對話

| 哪裡的對話 | 看得到嗎 | 怎麼運作 |
|---|---|---|
| 在你電腦上執行的 **Claude Code** | 看得到，全自動 | 外掛的 hooks 把事件送到你電腦上的地圖 |
| **Cowork** 的多步驟任務 | 看得到，但要 Claude 主動回報 | Claude 呼叫 `quest_plan` 回報整份步驟；問答、聊天、翻譯它通常不會 |
| **雲端的** Claude Code（網頁版，或桌面版選了雲端） | **看不到** | 對話跑在雲端的虛擬機裡，連不到你電腦上的地圖 |
| **一般聊天**（Chat） | **看不到** | 官方文件：聊天會忽略外掛的 hooks 和本機 MCP |

**怎麼分辨我的對話是本機還是雲端**：開新工作階段時，環境選項選在你的電腦上執行（Local）。雲端的對話網址是 `claude.ai/code/...`，跑在遠端的 Linux 虛擬機裡。按鈕名稱以你的畫面為準。

地圖待命時顯示「等待連線」，意思是它沒收到任何事件。最常見的原因就是上表的「看不到」，或是外掛更新前開的舊對話（開新對話就好）。

## 畫面怎麼看

### 關卡的六種狀態

每種狀態除了顏色，還有不同的圖示，色盲或看不清顏色也分得出來。

| 狀態 | 長相 | 意思 |
|---|---|---|
| 未開始 | 白色圓盤、灰邊、編號 | 還沒輪到 |
| 進行中 | 藍色圓盤、編號、向外擴散的光圈 | Claude 正在做，小機器人站在這一關 |
| 等你開門 | 橘色圓盤、鎖頭，其他地方變暗 | 需要你同意或回答 |
| 已通關 | 綠色圓盤、勾勾 | 做好了 |
| 施工中 | 黃色圓盤、扳手，上面掛「回頭修」牌子 | 做好的東西因為新需求要回頭修 |
| 已拆除 | 灰色圓盤、X、標題有刪除線，用斷掉的虛線接回原位置 | 你改變心意，這一步取消了 |

### 地圖上的各個區塊

| 位置 | 內容 |
|---|---|
| 左上 | 目前的世界與進度條（「關卡 2 / 5」，已拆除的關卡不算） |
| 左上下方 | 對話清單（有 2 個以上對話時才出現） |
| 左下 | 你剛剛說的話（Cowork 則是「這次的任務」） |
| 中間 | 關卡與小機器人，上方有對話泡泡，說它正在做什麼 |
| 右下 | 點一個關卡就顯示它的說明、小步驟、動過的檔案，最後一行才是技術細節 |
| 右上 | **終點城堡**，一開始被雲霧蓋住、標「未解鎖」 |
| 上方中間 | 計畫有重大改變時，藍色膠囊通知（新增幾關、拆掉幾關、幾關要回頭修） |

**世界**：前幾輪完成的工作會收合成一個綠色的旗子，放在左下角，點開可以看那一輪做了什麼，地圖不會越來越亂。

**全部完成**：所有關卡都通關時，小機器人會走到右上角的城堡門口，雲散開、城堡亮起來、通往城堡的路變綠，標籤變成「已完成」。你再說下一句話就開新的一輪。

### 什麼時候算完成

以計畫為準：

- **有待辦清單**：所有沒被拆除的關卡都通關才算完成，**包括你中途自己加的分支**。Claude 停下來只代表停在半路，不算完成。
- **沒有待辦清單的小任務**：整件事就是計畫，Claude 收尾（而且不是用問句結尾）時算完成。你在做到一半追加要求，算同一個任務。

### 小機器人的心情

| 心情 | 什麼時候 |
|---|---|
| 做事中（眨眼、上下輕跳） | 有關卡正在進行 |
| 等你（八字眉、冒汗、發抖） | Claude 需要你同意或回答 |
| 開心（笑眼、星星、跳得更高） | 全部通關 |
| 休息（閉眼、冒出 z） | 還沒開始，或 Claude 停下來了 |

### 邊緣水位與小把手

按地圖右上角的「縮到旁邊」，地圖收起來，螢幕左右兩側出現淡藍色水柱（底部相連，像一個杯子），旁邊有一個深色小把手。

- **一個任務一杯水**：任務進行中，上方有水流倒下來，水面帶著波浪慢慢漲；任務完成時漲到頂、亮一下，然後退掉換下一杯。
- **把手上的數字**（例如 `3/10`）是已經倒滿幾杯、總共幾個任務。
- **等你**：水變橘色閃動，把手變成橘色鎖頭「等你 · 對話名稱」，並跳出 Windows 系統通知。
- **全部完成**：水變綠色，四邊連成一圈。
- 水柱不會擋住你操作，滑鼠點擊會穿透過去。
- 點一下把手展開地圖；按住可以拖到別處，放開會自動貼回最近的左緣或右緣。

## 日常使用

### 同時跑多個對話

每個對話各有一份進度，彼此不會混在一起。

- 有 2 個以上對話時，左上角出現**對話清單**，每列有名稱（用資料夾名稱，重複的加編號）、小進度條和進度。**點一列就切換過去**，之後畫面固定顯示它。沒點過時，畫面自動跟著最近有動靜的那一個。
- 邊緣水位代表**你選的那一個**對話的進度。
- 對話結束就從清單消失；超過 6 小時沒動靜的也會移除。
- 沒選資料夾的對話在清單裡叫「未選資料夾的對話」。

### 有人在等你的時候

不管你選的是哪個對話，只要有任何一個在等你同意或回答，就會有四個提醒：清單上那一列變橘色、邊緣水位變橘色、小把手顯示「等你 · 名稱」、地圖縮起來時跳出系統通知。**要處理它，需要自己點清單切到那個對話。** 見[使用限制](#使用限制)。

### 小修改也看得到在做什麼

請 Claude 改一個小東西時，它通常不會列待辦清單。這時地圖靠 Claude 每次動工具的事件，即時顯示：

- **泡泡**：「正在看 index.html」「正在修改 style.css」「正在跑測試」。工具做完會換成過去式，「改好了 style.css，想下一步…」，Claude 思考的那幾秒也看得到剛剛做了什麼。
- **這次動過的檔案**：點關卡後，右下角列出「改了 style.css」「寫入 post.md」。
- **白話說明**：Claude 動手前會先補一句，例如「把按鈕改紅色：把送出按鈕的顏色改成紅色，讓人更容易看到」。這需要 Claude 配合，它沒補的話就只顯示動作。
- **完成時的一句話**：Claude 收尾訊息的第一句會顯示在泡泡。
- 只顯示檔名，不顯示完整路徑；跑指令只顯示類別（跑測試、安裝套件…），不顯示指令內容，因為指令裡可能有密碼。

### 在 Cowork 使用

Cowork 沒有辦法像 Claude Code 那樣自動同步（實測：Cowork 的 hooks 沒有把事件送到地圖），所以 Claude 要自己呼叫 `quest_plan` 回報整份步驟，內容跟 Cowork 右側的進度面板一樣。

- Cowork 的任務在清單裡叫「Cowork・任務名稱」，是**獨立的對話**，不會跟 Claude Code 的混在一起。
- 需要你動手時，Claude 會標「等你」；全部做完時，Claude 會寫一句白話結果。
- 多步驟的工作（下載、整理檔案、寫程式、研究後產出檔案）Claude 通常會主動回報；單純問答、聊天、翻譯不會。我在模擬 Cowork 的測試裡讓 Claude 做了 3 個沒提到 `quest_plan` 的多步驟工作，它 3 次都主動回報；另外 1 個純問答沒有。樣本很小，**不保證每次都會**。
- 想讓它更穩，可以在要求裡直接說「請用 quest_plan 回報進度」。

**第一次要先在 Claude Code 輸入一次 `/quest-map:open`**，把桌面視窗元件裝好。之後 Cowork 啟動時，如果地圖沒開，會自己把地圖打開。

## 使用限制

### 看不到的對話

- **雲端的 Claude Code** 和**一般聊天**看不到（見上面的表）。要讓雲端對話的進度傳回你的電腦，需要一個雙方都連得到的中繼服務，或讀取你的對話紀錄，目前沒有做。
- **外掛更新或換來源之前開的舊對話**看不到。舊對話載入的是舊設定，事件送不到地圖，**更新後要開新對話**。

### 同時跑多個工作

這是最需要先知道的限制。地圖是「你自己看著它」的工具，不是一個會替你調度的服務：

- **地圖一次只顯示一個對話的畫面**（你選的那個；沒選就跟著最近有動靜的）。
- 有對話在等你時，會有橘色提醒，但**地圖不會自動切到有狀況的那個對話**，也**不會替你排「誰最先需要你」的順序**。要看是哪個，得自己點清單，一個一個處理。
- **沒有集中處理的功能**：沒有收件匣、沒有排隊、沒有優先順序，也不會把幾個對話的狀況合併成一份待辦。
- **「有狀況」只指「要你同意或回答」。** 工具失敗只會讓泡泡寫「剛剛那一步沒成功」，不會提醒你；做了很久沒動靜也不會提醒。
- 想做成「最先有狀況的自動排最前面、集中處理」，需要另一種運作方式（一個常駐的背景服務，統一收集所有工作）。目前不做。
- 清單最多顯示 5 列，更多要捲動。
- 兩個對話開在**同一個資料夾**時，清單上會分成兩列（名稱加編號），但白話名稱和進度只能貼到其中最近有動靜的那個，可能貼錯。

### 「等你」的時機

- **橘色要等約 6 秒才會出現。** Claude Code 要等同意的提示停了約 6 秒，才會通知地圖。你一看到就馬上按同意，地圖來不及變橘色，這是正常的。
- **按下「同意」之後，橘色要等那個工具做完才會解除。** Claude Code 在你按同意的那一刻沒有發任何事件，只在工具成功或失敗時才通知。工具要跑很久（下載、長指令）時，橘色會一直在。橘色泡泡會寫「已等 N 分鐘」，超過 2 分鐘會提醒「如果你已經按過同意，這一步做完地圖才會更新」。
- Claude 的回覆用問號結尾時，會被當成「在問你問題」，變成等你。偶爾可能誤判。

### 進度與水位

- 水位是**估的**，除非 Claude 有拆小步驟並回報。沒有回報時，用「這個任務已經動了幾次工具」估，最多到九成，任務真的完成才倒滿。
- 工具跑得很快時，「正在…」只會閃一下，主要看到的是做完後的「改好了…，想下一步」。
- Cowork 全靠 Claude 記得呼叫 `quest_plan`，沒有「正在修改 style.css」這種自動動作，也偵測不到「等你按同意」，進行中那一步的水位固定從 30% 起跳。
- 關卡超過 7 個時，地圖只畫小機器人附近的 7 關，其餘用「前面 N 關已走過／後面還有 N 關」表示。

### 資料不保存

進度只存在記憶體裡。關掉地圖或換版本後，進度和「等你」狀態會清空，各對話要等下一次有動靜才會重新出現。**只有視窗的大小與位置、把手貼在哪一邊的哪個高度會記住。**

### 平台與環境

- **只在 Windows 實測過**：Claude Code 本機對話、Cowork 的 `quest_plan`、從 GitHub 安裝與更新。
- **macOS 和 Linux 桌面沒有驗證。** 尤其是透明的邊緣水位視窗、永遠在最上層、點擊穿透，在不同系統的表現可能不一樣。
- 需要 Node.js 18 以上，而且 `node` 要在 PATH 裡。
- 只支援**一個使用者、一台電腦**，用固定的本機連接埠 47600。同一台電腦有多個人同時登入並各跑一份，會搶同一個連接埠。連接埠可以用環境變數 `QUEST_PET_PORT` 改，但 hooks 和 MCP 也要設成一樣的值。
- 還沒有實測「Claude 要你按同意 → 變橘色 → 按了之後解除」在真實操作下的完整流程，這部分只用模擬的事件測過。

## 隱私與安全

- **全部在你的電腦上。** 地圖只監聽 `127.0.0.1`（本機），程式裡沒有任何把資料送到網路上的程式碼，也沒有遙測。
- **唯一的對外連線**是第一次下載桌面視窗元件（Electron），透過 npm（下載的檔案由 npm 與 GitHub 提供）。
- **外掛的 hooks 會在你的電腦上執行指令**（`node hook.js`），把 Claude Code 的事件送給本機的地圖。事件包含你說的話、工具的檔名與指令。地圖把它們放在記憶體裡，畫面上只顯示檔名、白話說明和 Claude 收尾的第一句話。
- **畫面上不顯示指令內容，也不顯示完整路徑**，因為指令裡可能有密碼或金鑰。
- `http://127.0.0.1:47600/stats` 只列事件名稱與次數、對話名稱與進度、最後動靜時間，**不含**你說的話、指令或檔案內容。
- 除錯模式（環境變數 `QUEST_PET_DEBUG=1`）會把收到的原始事件寫進檔案，**裡面有你說的話**。預設關閉，用完請刪掉 `events.log`。
- **本機連接埠沒有身分驗證。** 你電腦上的其他程式、甚至你瀏覽器開的網頁，都能對它送資料，最多只是讓地圖顯示不對的東西。關閉地圖的要求要帶特殊標頭，網頁送不出來。
- 桌面通知只在你的電腦上跳出，不經過任何伺服器。

## 疑難排解

先開兩個網址，能回答大部分問題：

- `http://127.0.0.1:47600/version`：地圖有沒有開、是哪個版本。看到「無法連線」是沒開；看到 **404** 是有開，但是很舊的版本。
- `http://127.0.0.1:47600/stats`：`sessionList` 列出地圖目前認得的對話，`events` 是收到的事件次數。

| 症狀 | 可能原因 | 怎麼辦 |
|---|---|---|
| 地圖一直顯示「等待連線」 | 這個對話是雲端、一般聊天，或是更新前開的舊對話 | 在桌面版 Code 分頁開新的**本機**對話。看 `/stats` 的 `sessionList` 有沒有你的對話 |
| `/quest-map:open` 說「這個對話跑在雲端」 | 你在雲端的對話裡 | 開新工作階段，環境選在你的電腦上執行 |
| 橘色一直不消失 | 你按了同意，但工具還在跑 | 等它做完，或在對話裡再說一句話（說話就會解除）。看泡泡上「已等 N 分鐘」 |
| 橘色沒有出現 | 你按得太快，或你的權限模式是自動同意 | 看到提示先等 10 秒；或把權限模式改成「每次詢問」 |
| 清單裡沒有 Cowork | Claude 沒有呼叫 `quest_plan` | 在要求裡說「請用 quest_plan 回報進度」。也可以請它「呼叫 quest_ping」，看連線通不通 |
| 地圖是舊版（`/version` 顯示 404 或舊版本） | 舊地圖沒關乾淨 | 見下方「關掉舊地圖」 |
| 第一次下載失敗 | 網路或 Node.js 問題 | 確認 `node --version` 是 18 以上、網路連得到 npm，再輸入一次 `/quest-map:open` |
| `claude plugin marketplace add` 失敗 | 沒裝 git | 安裝 git 再試 |

**關掉舊地圖**（先列出，確認路徑是闖關地圖的再關）：

```powershell
Get-Process electron -ErrorAction SilentlyContinue | Select-Object Id, Path
```

```powershell
Get-Process electron -ErrorAction SilentlyContinue | Stop-Process
```

**`quest_ping` 的三種回報**（在 Cowork 或 Claude Code 請 Claude 呼叫它，用來測連線）：

| 回報 | 代表什麼 |
|---|---|
| 成功，闖關地圖有收到 | 連上了，而且是新版 |
| 地圖有開，但是舊版（對方回 404） | 電腦上跑的是舊版地圖，完全關掉再開 |
| 失敗，連不到闖關地圖 | 沒開，或這個環境連不到你電腦上的地圖（例如雲端） |

## 更新與解除安裝

### 更新

**Claude Code（命令列）**

```bash
claude plugin marketplace update ai-quest-map
```

```bash
claude plugin update quest-map@ai-quest-map
```

**Claude 桌面版**：Customize > Plugins > 點開 **AI 任務闖關地圖** > 按 **更新**；按不動就到市集按 **Check for updates**。

然後**開新的本機對話**。如果地圖還開著舊版，它會自動換成新版（0.11.0 以後的版本才有這個功能；從更舊的版本升級要先手動關掉舊地圖一次）。

### 解除安裝

```bash
claude plugin uninstall quest-map@ai-quest-map
```

```bash
claude plugin marketplace remove ai-quest-map
```

桌面版：Customize > Plugins > 打開 quest-map > **Remove**。

然後關掉地圖（按右上角 X），想清乾淨可以刪掉這兩個資料夾：

- `%USERPROFILE%\.quest-map`：桌面視窗元件。
- 視窗位置的記錄，通常在 `%APPDATA%\quest-pet`。

## 運作原理

| 元件 | 做什麼 |
|---|---|
| **Hooks** | 在 Claude Code 的這些時刻通知地圖：工作階段開始與結束、你送出一句話、工具要開始與做完（成功或失敗）、需要你同意、Claude 停下來。自動，不花 Claude 的注意力 |
| **MCP 工具** `describe_quest` | Claude 替關卡補上白話名稱、說明與小步驟 |
| `quest_progress` | Claude 回報這個任務做完幾個小步驟 |
| `quest_plan` | Cowork 用：Claude 回報整份步驟清單與每步的狀態 |
| `quest_ping` | 測試連線 |
| **Skills** `plain-levels`、`open` | 教 Claude 什麼時候呼叫上面的工具、白話怎麼寫；`/quest-map:open` 打開地圖 |
| **桌面程式** | Electron 寫的小視窗：地圖、邊緣水位、小把手，以及只聽本機 `127.0.0.1:47600` 的接收埠 |

狀態由 hooks 負責，文字由 Claude 負責。就算 Claude 忘了呼叫 MCP 工具，地圖照樣會動，只是關卡名稱會是待辦清單的原文。

**環境變數**（進階）：`QUEST_PET_PORT` 連接埠、`QUEST_PET_DEBUG` 除錯記錄、`QUEST_PET_NO_AUTOLAUNCH` 不要自動打開地圖、`QUEST_PET_RUNTIME` 桌面元件的安裝位置。

## 開發

```bash
cd plugins/quest-map/app
npm install
npm test
```

```bash
npm start
```

`npm start` 開地圖，另開一個終端機跑 `npm run demo`，會送一串假的進度，不接 Claude Code 也能看效果。

| 檔案 | 內容 |
|---|---|
| `quest-map.html` | 地圖本體，也是網頁示範版的來源。改完跑 `npm run build` 產生 `app/map.html`（外掛安裝時不會建置，所以 `map.html` 要一起提交） |

| `plugins/quest-map/app/main.js` | 桌面視窗與本機接收埠 |

| `plugins/quest-map/app/edge.html`、`battery.html` | 邊緣水位與小把手 |
