# 闖關地圖：白話名稱與小步驟

使用者桌面上有一張闖關地圖和螢幕邊緣的水位，把你的待辦清單畫成關卡。看的人多半不懂程式，他想知道三件事：做到哪了、這次要做什麼、跟剛剛比哪裡不一樣。

每個任務是一杯水。任務裡的小步驟每做完一步，水就漲一格；任務完成，水倒滿。

任務的狀態（未開始、進行中、完成、等使用者）會自動同步，你不用回報。你負責兩件事：文字，以及任務裡面做到第幾步。

把任務拆成小步驟、做完一步報一步，也是在幫你自己：工作很長時，不容易忘記做到哪裡。

## 0. 先判斷你在哪裡

- **Claude Code**：狀態由 hooks 自動同步，照下面第 1 到 2 節做。
- **Cowork（有「進度」面板）或一般聊天**：沒有自動同步，改用 `quest_plan`，不要用 `describe_quest`。
  - 任務一開始就呼叫一次，送出 `goal`（一句白話，這個任務要完成什麼）和整份 `steps`（白話步驟名稱，每步有 `status`：`pending`、`in_progress`、`completed`）。
  - 之後每次進度有變動（開始某一步、做完某一步、新增或拿掉步驟）就再呼叫一次，**每次都送完整清單**，內容跟你的進度面板一樣。
  - 同一個任務每次填同樣的 `task_id`（短的英文代號）。
  - 需要使用者動手或回答時，填 `waiting_for`，寫出具體要他做什麼。
  - 全部做完時，在 `summary` 寫一句白話結果。
  - 如果工具回答「這裡不需要 quest_plan」，代表你其實在 Claude Code 裡，改照下面的做法。

## 1. 建立或改動清單後：呼叫 `describe_quest`

- 建立待辦清單之後呼叫一次，涵蓋每個項目，並提供 `world` 和 `goal`。
- 之後清單新增或改寫項目時再呼叫，只傳有變動的項目。
- 只是把項目標成進行中或完成，不用呼叫。

每個項目要寫：

- `title`：8 個字以內，講使用者會得到什麼。寫「做出表單畫面」，不寫「建立 form.html」。
- `plain`：一句話，說明這關在做什麼、為什麼需要。不要出現檔名、指令、套件名。
- `tech`：技術細節放這裡，一行，例如「POST /api/signup，寫入 SQLite」。
- `steps`：你打算怎麼做這個任務，拆成 2 到 5 個小步驟，照執行順序排，每個 10 個字以內的白話。例如「做出表單畫面」可以是 `["排好欄位", "加上送出按鈕", "調整手機版面"]`。很小的任務 1 到 2 步就好，不要硬湊。

`world` 是這一輪工作的名字，帶一點遊戲感，例如「報名表單森林」「首頁平原」。使用者用什麼語言，你就用什麼語言。

## 1b. 沒有待辦清單的小修改：動手前也呼叫一次

使用者請你改一個小東西、你不打算列清單時，開始動手**之前**先呼叫一次 `describe_quest`：

- `task` 填 `"1"`。不要為了這件事另外建立待辦清單。
- `title`：8 個字以內，例如「把按鈕改紅色」。
- `plain`：一句白話，說明你要改的是什麼功能、為什麼，例如「把送出按鈕的顏色改成紅色，讓人更容易看到」。不要出現檔名、指令、程式碼術語。
- `steps`：小到一兩步的修改可以不給；有三步以上才給。
- 使用者只是在問問題、不需要你動手改東西時，不用呼叫。

這句話會顯示在地圖上，讓不懂程式的人知道你正在改的是哪個功能，不是只看到「正在修改 style.css」。

## 2. 每做完一個小步驟：呼叫 `quest_progress`

- 開始做一個任務後，每完成 `steps` 裡的一步，就呼叫一次，`done` 填這個任務到目前為止做完幾步。
- `task` 可以省略，代表目前進行中的任務。
- 做到一半發現步驟數不對，用 `total` 更正，或再呼叫 `describe_quest` 更新 `steps`。
- 任務整個完成時不用呼叫，照常把待辦標成完成，水會自己倒滿。

## `task` 要填什麼

- 用 TaskCreate 建立的項目：填任務編號，例如 `"3"`。
- 用 TodoWrite 建立的項目：填它在清單中的第幾項，例如 `"2"`，或填項目原文。
- 沒有待辦清單的單一任務：填 `"1"`。

## 注意

工具回報地圖沒開，或呼叫失敗，都不影響你的工作。不用向使用者提起，繼續做事。
